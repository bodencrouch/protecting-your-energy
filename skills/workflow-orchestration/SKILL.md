# Phase-aware workflow orchestration

When this workflow is active, make capability selection a checkpoint before each
substantial phase or change of approach. Apply an appropriate existing workflow
whenever one is available. Routine steps can reuse an already loaded workflow;
do not load skills solely to demonstrate activity.

1. Recover the intended outcome, every current request and constraint, prior active
   directives, project authority, and evidence already available. Follow-ups add or
   steer work unless the user explicitly cancels, pauses or replaces it. Resolve
   unclear referents from accessible context before interpreting them. For
   historical or comprehensive requests, do this before paraphrasing the request
   or listing assumptions. A hook or prompt that requires a pre-tool rewrite does
   not override context recovery or the user's actual directive; show a rewritten
   prompt only when the user asks for one.
   For repository work, inspect dirty files and unpublished commits, recover their
   purpose and ownership, and include coherent unfinished work in the delivery
   queue. Use separate commits or branches where helpful; preserve other owners'
   changes and review privacy and current publication authority before pushing.
   Isolation protects work but does not discharge the obligation to finish it.
2. Identify the next phase: discovery, planning, implementation, verification,
   review or delivery. Consult the host's actual installed capability catalog for
   relevant skills, plugin commands, agent roles and tools. Prefer project-owned
   runbooks and skills, then maintained domain workflows. Compare applicability,
   prerequisites, authority and expected outputs; a keyword match is insufficient.
3. Read the chosen entrypoint before using it, then load only the references needed
   now. Reuse compatible workflows already in context. Honor current user scope,
   permissions and project constraints when a generic recipe differs. An explicit
   instruction needs no second approval merely because a skill discusses consent
   for inferred preferences. Never invent an installed command or agent role.
4. Apply the specialist procedure to the real deliverable. Use commands/scripts for
   deterministic work. Delegate independent bounded work when authorized and useful;
   give each worker source access, constraints, a distinct write scope and concrete
   acceptance evidence. Keep urgent dependent work local, integrate results, and
   respect the host's model-routing instructions and resource limits.
5. Reassess selection at a phase transition, new evidence, a correction, failure or
   recurring bottleneck. If no relevant workflow exists, proceed using the best
   available procedure; report a missing capability only when it affects delivery.
   Improve the applicable workflow when maintenance is authorized, preserving the
   task itself. Do not let workflow upkeep displace the requested result.
6. Before concluding, reconcile every message clause and all active directives with
   executed work and observed results. Preserve unresolved items and exact blockers.
   A completed step, skill invocation or background launch does not complete the
   broader task. Continue authorized independent work while useful actions remain.

A brief progress update can name the phase, chosen capability and why it fits.
Avoid dumping the catalog or making the user choose the workflow. Distinguish
planned selection, actual invocation, worker results and verified task completion.

For durable changes to agent behavior, consult
[policy placement](../../references/policy-placement.md). Keep project facts and
private incident records outside distributable plugin instructions.

## Keep the authorized execution loop active

For work spanning multiple objectives, archives, repositories, machines or agents,
keep one coordination index linked to each project's authoritative directive and
acceptance records, plus one evolving evidence-to-action map. Do not replace
project-specific sources of truth. Parallelize independent discovery, analysis,
implementation and verification when the expected schedule, coverage or risk benefit
exceeds coordination and resource costs. Do not split work into exclusive sequential
groups without a dependency or ownership reason. Keep routine one-step tasks local
and serial when parallelism adds no net value. Serialize shared mutable resources,
required evidence order and explicit authority boundaries.

After each material result, inspect the live directive ledger and acceptance
criteria for the next useful action. Look for unmet requirements, recoverable
context, prerequisites, integration gaps, observed defects, verification needs
and requested delivery. Use dependencies to identify the next useful action; when
several strands compete, rank them using the broad-work criteria below. Do not wait
for another prompt when the next step is already authorized.

Treat inventory as decision input, not a stopping point. As each useful result
arrives, record its source and provenance, finding, confidence and limits, affected
objective, canonical destination or owner, next action, dependencies and acceptance
evidence. Harvest actionable findings from current output, connect overlaps and
conflicts, and update priorities immediately. Start the highest-impact authorized
reversible action while slower scans continue; reuse completed evidence instead of
repeating discovery. Rank by objective impact, dependency unblocking, risk reduction,
evidence confidence and total effort, within resource limits and project rules.
Do not optimize scan speed or report volume at the cost of a correct, recoverable
result.

For file and data consolidation, resolve the destination from the project's existing
component layout and authority before moving anything. Honor the requested verb:
"move" is not satisfied by a copy or symlink. Do not invent generic recovery,
import or host-mirror trees. If no established destination exists, or provenance,
conflicts, capacity or active use remain unresolved, retain the item as open and
name the evidence needed to make the move safe. Keep the source intact until the
destination contents and provenance are verified; then complete the requested
source removal and verify that disposition against the requested outcome.

Reuse the installed skill, prompt, command or agent workflow that fits that action.
When blocked, advance independent authorized work and preserve the blocking
condition and continuation point. Observe running operations before claiming
background progress. Do not manufacture unrelated goals, run endless speculative
cleanup, repeat already sufficient checks or expand publication permissions.

Give delegated workers distinct read/write scopes and request decision-ready
receipts: what the evidence establishes, what remains unknown, how the finding
changes the active plan, and the best authorized next action. After timeouts or
partial inventories, retain exact coverage and resume the uncovered surface while
independent work proceeds. A status update, inventory report, plan or set of
completed substeps is not completion; integrate results and verify the requested
outcome against every active directive before stopping.
If a requested source is inaccessible or only partly covered, name that source and
the exact boundary, keep it open in the evidence-to-action map, and continue other
authorized sources that can still advance the task.

When the user wants educational commentary, close a substantive update with one
short applicable insight, for example "The useful agentic pattern here is ...".
Explain the concrete pattern and its effect rather than appending an empty slogan.
Respect artifact-only output formats and the user's preferred level of detail.
