# Finish the useful increment

Bind the requested result, actual completion proof, current artifact, active
owner, dependencies and latest useful observation. Preserve explicit sequencing
and project constraints. Progress, a running process and a plan are not proof
that the result works.

Reassess after a new dependency, repeated failed approach or a material change
in remaining effort. Use analogous completed work and present blockers where
available. Distinguish active work, machine waiting and unknown effort. Update
remaining effort from the new evidence; do not treat the original optimistic
estimate as an obligation to keep going unchanged.
Honor a user-stated time, effort or spending cap. Reach the best permitted
checkpoint within it, preserve the remaining scope and report what is unfinished.

Before switching approaches or deferring, preserve the current artifact, exact
state, last useful result, unresolved facts, attempted approaches, owner, source
links and next executable action in [continuity](../../references/continuity.md).
Do not delete earlier work, infer abandonment or start a duplicate job.

Compare forward cost and value of continuing, changing the approach, splitting
a useful demonstration, or deferring a speculative branch. A smaller honest
artifact can help develop the idea while the full result is being built. It
does not satisfy a full-result request unless the owner explicitly accepts the
scope change. Do not silently redefine success or stop the core authorized work
merely because a self-imposed budget ended. A consequential scope decision gets
one concrete choice with the prepared result and retained wider objective.

Continue reversible in-scope work when the next action is clear. Use a bounded
experiment when it can resolve a blocker, respecting explicit no-test rules.
Verify the specific artifact with allowed observable checks. Ask for permission
only at an actual authorization boundary. If all permitted approaches are
blocked, name the missing condition, preserved state and exact restart action.

Return the usable increment and the remaining blocker or completion proof.
Keep reassessment mechanics behind it unless the owner requested an evaluation.
A checkpoint budget is a practical choice, not an academically optimal cadence.
