# Bookmarked native input hydration

`scripts/native_context.py` provides `load_current_sources(current, derived_root, read_source, guarded)` for explicit invocation by a continuation consumer. It is an independent standard-library module, with no CLI, model call, hook, configuration mutation, or stored output. The consumer supplies its existing guarded derived-source reader and path guard. The consumer must apply its display sanitizer to the composed output.

The saved current object supplies one `current_source_bookmarks` reference containing `path` and `sha256`, plus the eligible `source_threads`. The version 1 bookmark file supplies each thread's original native path, first-header SHA, observed size, and exact pinned user-row metadata. The helper reads the bookmark under the configured derived root and reads only the first header and selected row ranges under `~/.codex/sessions`. Every native path component must be a real directory or regular file, with no symlink traversal; the existing sealed and request-only guard applies.

The first `session_meta` must identify its own thread and classify its own source as `cli` or `vscode`. Later copied headers cannot authorize a child session. Each selected row must match the pinned raw SHA, exact byte and newline boundaries, native message ID, timestamp, user role, and exact `['user.text']` marker. Control and delegation prefixes are refused. Every content block must be `input_text`; all text blocks remain in order with exact text pointers and hashes. `text_blocks` preserves the individual blocks; `text` concatenates them without inserting a separator. No creator account fields are returned. Native origin and kind markers qualify the record, but do not independently prove authorship or owner adoption.

The return object has `status` (`not-configured`, `read`, or `unavailable`), `configured`, `snapshot_complete`, `records`, `threads`, `bookmark`, and `qualifiers`. Each record includes full text, ordered blocks, classification, and exact source receipts. Thread receipts describe the authenticated ranges and observed snapshot size. `read` means all requested bookmarked rows were authenticated; it does not mean the latest inputs were recovered. `live_tail_scanned` is always false and `newer_human_inputs_may_exist` is always true. The unselected prefix and any appended tail are not authenticated. Current caller input takes precedence over these historical inputs.

Limits are four selected threads, 64 records total, 128 KiB of text, a 256 KiB bookmark, 64 KiB first header, 1 MiB per raw row, and 16 MiB total requested native bytes including header and boundary probes. A 30-second cooperative deadline is checked between bounded reads; it cannot interrupt a blocked OS operation. Whole text must fit; there is no silent clipping. Missing rows, duplicates, invalid metadata, changed pinned bytes, guarded paths, concurrent source change, or overflow return `unavailable` with a fixed diagnostic and no partial source bodies. Concurrent appends during a thread read also fail safely, even if its earlier pinned bytes remain unchanged. A consumer requiring original inputs must stop generation on that configured failure. An absent bookmark returns `not-configured` without reading sources. Passthrough kind metadata may be a dictionary or a JSON-encoded dictionary, with the same strict duplicate-key, finite-value, and exact-kind checks.

The module reads exact bookmarked snapshots only. The observed file size has no pinned complete-prefix SHA and therefore cannot establish append-only history or full live coverage. A newer file may be accepted when the pinned header and rows still verify, with freshness explicitly unresolved.

The ordinary `continuation.py` consumer first invokes the hash-pinned refresh helper with its already-loaded guarded IO callbacks. This route captures selected complete native prefixes and a new metadata descriptor in RAM, then passes that descriptor through an exact-match RAM reader to the hydration module. The RAM descriptor has its own identity and SHA; it does not masquerade as a changed bookmark file. The previous file receipt remains in the separate `freshness.proof` field. No bookmark, state reference or source body is written.

`freshness.prefixes` describes the refresh observations and complete-prefix authentication. The hydration thread receipts still describe only their exact row reads; their `whole_prefix_authenticated: false` is not replaced by the separate proof. Later appends remain unverified. Refresh failure returns no partial bodies and has no stale-bookmark fallback; configured failure also stops canonical retrieval and native generation. Refresh has a 30-second cooperative deadline, followed by the existing hydration deadline and, on success, the separate retrieval deadline. The refresh byte budget describes captured prefix sizes, not total repeated IO: each prefix is reread, with an additional prior-prefix verification when available.
