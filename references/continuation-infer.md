# Infer and draft from a current cue

`scripts/continuation_infer.py` explicitly runs a bounded RAM-only route using the installed Claude CLI's existing authentication and default model. It uses the existing safe-mode, no-tools, strict empty MCP configuration, no-session-persistence flags and structured-output transport. It does not install a service or hook, select a provider, change model configuration, or establish automatic discovery by another client. Native session-persistence flags do not guarantee zero provider retention or bookkeeping.

The default route captures current continuity context and refreshes required native inputs once. It then infers a provisional purpose, reader effect, local scope, optional creative choices, uncertainties and at most two search probes. A plan may decide memory is not useful. The compiler preserves the current cue and corrections, searches through the existing canonical runtime when needed, and retains the original source qualifications. One direct writer call receives the same captured native inputs and at most six self-contained hydrated source units. It selects sources only for specified artifact decisions and returns the actual artifact. It can choose no archival source units. There is no mandatory applicability, critic or revision chain.

`--direct` skips planning and implicit archival retrieval for a clear current request. Explicit `--query` facets or `--unit-id` anchors still request canonical retrieval. The host can supply an already formulated plan through stdin instead of calling the planner; the plan remains unverified inference. Current corrections take precedence over both older source context and the plan. Creative options and search wording are not requirements, recovered facts or durable user traits.

Task selection uses the compiler's explicit IDs, recorded execution associations for bare resumes, and existing lexical limits for substantive cues. When a cue leaves a saved task ambiguous, its artifact and native inputs are not loaded. An existing host can resolve the task and pass `--task-id`; the standalone planner cannot infer from inputs it never reads. An execution association establishes a recorded task scope, not semantic applicability or human identity. Without configured native inputs or useful archive selection, the artifact remains a source-limited proposal.

A saved explicit native assistant proposal can be loaded through `chat_artifact.native_proposal` in the selected current record. It remains separate from original user inputs and owner evidence. An unavailable required proposal stops before the planner, writer and canonical query; the route does not manufacture a replacement for the missing draft. See [proposal source qualification](chat-proposal.md).

Invoke with an ordinary cue argument. Optional arguments are `--task-id`, paired `--execution-harness` and `--execution-context-id`, repeatable `--query` and `--unit-id`, repeatable `--correction`, `--corrections-stdin`, `--direct`, `--meaning-check`, `--include-analysis`, `--timeout`, and `--native-timeout`. Alternatively `--input-stdin` reads a JSON object containing any of `cue`, `corrections`, `plan`, and `current_artifact`; `meaning` is additionally allowed only with `--direct --meaning-check`. A stdin cue conflicts with a positional cue. Corrections and artifact proposals stay in RAM. No output-file argument exists.

A supplied plan has exactly `purpose`, `reader_effect`, `local_scope`, `creative_options`, `uncertainties`, `memory_useful`, and `probes`. Text fields and probes are bounded to 2,048 characters; creative options have at most three entries, uncertainties eight, and probes two. If `memory_useful` is false, probes must be empty. Explicit facets keep priority within the existing six-facet total; duplicate or omitted probes remain reported as hypotheses. A caller-supplied artifact is a proposal, not historical evidence or acceptance.

Stdout contains the artifact, selected unit IDs, uncertainties and body-free technical receipts. `--include-analysis` additionally includes the provisional plan and private proposed source uses. Each selected unit requires a use explanation tied to an artifact decision and its source limitations. Source IDs must come from the actual hydrated candidates. An owner-attributed-source label requires the existing effective owner-source flags; it does not prove original actor identity, copied-span endorsement, or belief adoption. Context-only source use is allowed with its qualifications.

The native writer returns exactly `artifact`, `uncertainties`, and a `source_uses` object with every available unit ID as a required key. Each slot is null for an unused source or an exact use object containing `artifact_decision`, `use`, `evidence_role`, and `limitations`. One source can inform multiple decisions in its explanation. Unknown or missing keys are rejected; zero available units require an empty object. The route derives the public `source_basis`, private source-use list and `source_limited_proposal` from validated non-null slots. The latter is true whenever no archival unit is selected, even when current caller or native inputs suffice. A rejected response leaves no delivered artifact and reports a fixed validation code and failed stage, plus its compact JSON hash, size and known-field type/count summary. Response bodies, unknown keys and arbitrary exception text are not exported by these diagnostics.

Caller plans and artifact proposals pass through the pinned credential display sanitizer before retrieval or native transport, as does a generated plan before reuse. The receipt distinguishes original versus display-rendered caller-proposal JSON hashes; the artifact-input hash describes the rendered JSON string. Rendering does not verify authorship or source facts, and its recognizable-credential scope does not promise detection of every secret.

Limits retain the existing transport's 1 MiB prompt/output caps and 128 KiB hard artifact cap, with a default draft target below 16 KiB. Stdin is bounded to 256 KiB. Retrieval has a 1–120 second deadline; each native call has a 1–600 second deadline, default 300. The default route uses at most two native calls; direct or supplied-plan routes use one. Required native-source failure stops before planning, retrieval and writing. Invalid schemas, unknown source IDs, overstated source roles, failed retrieval or transport failure leave an unsuccessful deliverable. There is no silent clipping or stale-source fallback.

The compiler APIs are `prepare_context(args)` and `retrieve_context(prepared, args, probes=None, *, retrieve=True)`. The prepared context is an in-process snapshot, not an externally supplied attestation format. `compile_context(args)` composes these APIs to preserve its existing behavior. The inference API is `run_infer(args, transport=None, invoke=None, host_plan=None, current_artifact=None, host_meaning=None)`; injected native calls use the existing four-argument transport contract. The transport's extra schemas exist only in the privately loaded module's RAM for their call and are removed afterward. The writer receives the provisional brief without search probe wording.

`--meaning-check` adds an optional schema and evidence-location contract at the existing planner-to-writer boundary. The default plan, writer response, public output and call counts remain unchanged. The existing planner can add a `meaning` object with exactly `candidates` and `rationale`. Zero candidates are appropriate when the request is clear or competing readings lack useful support; the rationale explains that choice. At most two candidates may identify genuinely different plausible readings that would materially change the artifact. Each candidate has exactly `id`, `interpretation`, `meaning`, `artifact_difference`, `support`, and `counterevidence`. Its `meaning` object has exactly `actor`, `experiencer`, `target`, `relation`, `polarity`, `modality`, and `condition`; unspecified slots are null. Interpretation, difference and rationale have a 1,024-character limit, scope slots 512, and IDs use 1–32 ASCII letters, digits, underscores or hyphens. Duplicate IDs and exact duplicate candidate content (interpretation, the seven scope slots and artifact difference) are rejected, independent of object key order or evidence differences. Different interpretations or consequences may share the same nullable scope. Semantic difference and plausibility are not mechanically established.

The contract captures exact post-sanitizer text fields once in RAM before retrieval. Its role catalogue contains the current cue, individual corrections, qualified original native input rows, the selected artifact proposal, explicit related assistant proposals and an optional caller artifact proposal. The supplied role and source pointer come from route bindings, not model claims. Generated source accounts remain hypotheses in the existing context payload and are excluded from this anchor catalogue. Proposals cannot provide sole primary support. At least one support anchor must reference the current cue, a correction or qualified native input; historical native input still retains its authorship, snapshot and adoption limits, and current corrections retain priority. The planner and writer receive JSON-pointer metadata and rendered text hashes for fields already present in their payloads, without duplicate source bodies. Limits are 80 handles, 512 KiB per field and 1 MiB combined UTF-8 source text; exceeding a limit fails without clipping. The existing 1 MiB native transport prompt preflight remains authoritative for the complete payload, including JSON overhead.

Support and counterevidence each contain at most four exact `{handle,quote}` objects; support is nonempty. Quotes are at most 1,024 characters and must occur exactly once within the referenced single field, counting overlapping occurrences. Unknown handles, duplicate anchors, nonexact or nonunique quotes, and quotes touching any part of the display sanitizer's credential placeholder are rejected. Candidate validation occurs before retrieval and writing when a supplied plan or direct bundle makes that possible; generated candidates are checked immediately after planning. Matching a quote establishes its location and a candidate's stated support, not entailment, truth, human intent or adoption. Captured current inputs and proposal fields must remain unchanged through retrieval.

The opt-in writer adds `meaning_dispositions`, an object with every existing candidate ID as a required key and no extra keys. Each value has exactly `status`, `explanation`, `distinguishing_evidence`, `artifact_consequence`, and `artifact_quotes`. Status is `resolved`, `rejected`, or `unresolved`. Resolution and rejection require at least one exact unique current/native distinguishing anchor and an explanation of how it distinguishes the interpretations. Qualified retrieved history may inform a disposition under current-input priority, but cannot replace the required current/native anchor. Explanations and consequences are bounded to 2,048 characters; distinguishing evidence has at most four anchors. Every disposition must quote one to three exact unique artifact spans, each at most 1,024 characters, showing the stated consequence. The opt-in response is sanitized before artifact-quote checking, so these locations refer to delivered display text. Unresolved material differences call for useful variants or a shared artifact valid under retained readings; silently selecting one is disallowed by writer guidance. Schema and exact locations cannot prove that the explanation distinguishes readings or that the actual artifact fulfills its consequence; independent artifact review remains necessary.

`--direct --meaning-check` requires an explicit stdin `meaning` bundle, or `host_meaning` through the Python API, and retains one writer call. An explicitly supplied zero-candidate bundle with a rationale is allowed. A non-direct supplied plan instead carries its own extended `meaning` field. Conflicting routes or a missing direct bundle fail before generation; no extra inference, critic or revision call is introduced. The SHA-pinned pure helper is loaded only for the opt-in route, and existing compiler/transport pins remain unchanged. Public receipts expose hashes, counts, roles and the judgment `anchors and schema validated; meaning unverified`; candidate and disposition bodies appear only with `--include-analysis`. Generated interpretations remain provisional proposals and never become current corrections or owner facts.

`draft-produced` establishes schema-valid delivery only. Inferences, source-use explanations and creative choices remain model proposals. Objective success, emotional effect and owner acceptance are not established by this route and require evaluation of the delivered artifact.

The optional meaning contract is experimental. An invalid generated quote withholds delivery rather than silently dropping a candidate or falling back to unchecked writing. A bounded native regression delivered a clear creative control with zero candidates, but failed its ambiguous case at the quote-location gate. This establishes functional validation and a delivery limitation, not improved interpretation or personalization. Keep the default route available and evaluate complete artifacts independently before adopting the option for a workload.

Writer guidance also separates character beliefs from narrative verdicts and preserves felt stakes alongside observable outcomes. It rejects invented obligatory moral framing and permanent creative restrictions unsupported by the current purpose. These instructions address an observed fidelity failure; they are not a validated guarantee that the native writer will follow them.
